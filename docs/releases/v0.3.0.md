# AutoOPS v0.3.0 — Portfolio Release Candidate

AutoOPS v0.3.0 packages the post-v0.2 operational hardening work into a clear release boundary for portfolio review.

## Highlights

- Read-only artifact health assessment for backups, exports, reports, and logs.
- `autoops-artifact` health gate with human, JSON, and CSV output.
- Manifest-driven batch assessment for multiple expected artifacts.
- Explicit `missing` state so one absent expected artifact does not hide the health of the rest of a batch.
- File freshness reporting that surfaces future timestamps as clock-skew anomalies.
- Hardened CSV output that neutralizes spreadsheet-formula prefixes, including whitespace-prefixed forms.
- Stronger operation/workflow validation and safer exception normalization at automation boundaries.
- Existing disk, environment, and combined preflight diagnostics remain local and read-only.

## Safety boundary

This release does not add destructive automation, remote execution, credential handling, network probing, or implicit filesystem mutation. State-changing `Operation` instances remain dry-run by default and require explicit caller intent before execution.

Artifact checks inspect filesystem metadata and configured expectations only. Missing artifacts are reported as health state rather than created, repaired, downloaded, or deleted.

## Release verification

Before tagging `v0.3.0`, require the GitHub Actions matrix to pass, including the build/install sanity job. The release-version regression test requires runtime `autoops.__version__` to match installed package metadata and to equal `0.3.0`.

## Portfolio demo

A concise recruiter-facing demonstration can combine local preflight diagnostics with a batch artifact health gate:

```bash
autoops preflight . --json
autoops-artifact --manifest artifacts.json --json
```

These commands demonstrate structured operational reporting and CI-friendly health signals without changing the host or contacting remote systems.
